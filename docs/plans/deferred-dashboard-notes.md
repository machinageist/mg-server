# Deferred Dashboard Notes

> Parked for later. This is a memory aid, not an approved feature, information architecture, or implementation plan.

## Why it is deferred

The dashboard should grow from Jeff's own use, language, and visual decisions. Do not add a dashboard route, navigation item, homepage section, data model, or public claim until Jeff has developed the concept enough to feel ownership of it.

## Ideas worth remembering

A future dashboard might connect some combination of:

- what is running now;
- what is currently being built;
- what has been verified;
- recent writing or operating notes;
- relationships inside the homelab;
- incident, restore, and maintenance evidence;
- restrained process vitals;
- measured power, hardware reuse, or maintenance information where real evidence exists;
- explicit planned, active, verified, maintained, and retired states.

These are prompts, not requirements. The dashboard should not become a generic admin panel, invented observability surface, or new public promise.

## Revisit gate

Revisit only when Jeff can answer, in his own terms:

1. Who is the dashboard for?
2. What should it help that person understand or do?
3. Which information is real and maintainable today?
4. What belongs on the homepage versus a separate surface?
5. What should remain private?
6. What visual metaphor feels personally owned rather than borrowed?

Until then, improve the current site through small visual and evidence-quality changes without adding new sections or concepts.
